## Cache headers and static asset serving

server.js implements three-tier caching strategy:

1. **Immutable hashed assets**: `app.use('/assets', express.static('dist/assets', { maxAge: '1y', immutable: true }));` — Static assets in `/assets` (JS, CSS) are hashed by Vite and cached for 1 year with immutable flag. Correct for production builds where hashed filenames change on every update.

2. **Short-lived HTML**: `app.use(express.static('dist', { maxAge: '1h' }));` — HTML and manifest files cached for 1 hour. This balances freshness with performance. Users get updates within an hour without aggressive cache busting.

3. **API caching**: Health endpoint gets `Cache-Control: public, max-age=60` (1 minute). Other API endpoints get `Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate` (never cached). Dynamic data correctly excluded from caching.

Compression middleware moved to line 64 to apply to all responses before static file serving — compression must wrap the entire middleware stack to compress both static files and API responses.

Cache control middleware at lines 71-79 sets headers before the request reaches route handlers. The conditional logic correctly identifies `/health` and applies different headers.
